## 打开与部署

完整项目为纯 HTML、CSS、JavaScript 和本地素材，无框架、构建步骤、后端或账号依赖。解压后可打开 index.html；推荐通过普通静态 HTTP 服务预览，以便检查资源和浏览器行为。除指定的 Umami 外，不加载第三方字体、图片或声音。

更新现有 GitHub Pages：

1. 将完整 ZIP 内容解压到现有发布目录；index.html 应位于发布目录最外层。
2. 覆盖本项目同名文件，保留用户已有的 CNAME、真实内容、仓库配置和其他文件；本项目不修改 DNS。
3. 沿用现有 GitHub Pages 设置提交发布。不要上传 ZIP 文件本身来代替网页文件。

站内本地资源使用相对路径，支持域名根目录与 /仓库名/ 子路径。404 页面根据域名或可用仓库路径返回首页。社交预览绝对地址仍指向 https://yi.wang/。本说明不代表已执行线上部署。

主要文件：

- index.html、404.html、styles.css：内容、布局和静态页面。
- world-time.js：连续设备本地时间模型。
- camera-controller.js：统一镜头控制器。
- world-state.js：五种天气、四季、统一外观与质量档位。
- scene-painter.js：外观变化时预绘制、缓存和双画布交叉淡入。
- script.js：按需调度、导航、相册、书本、声音和设置。
- assets/、assets/mobile/：桌面及手机 WebP 素材。
- .nojekyll：GitHub Pages 静态资源支持。
- ARCHITECTURE.md、REQUIREMENTS.md、ASSET-PROMPTS.md、VALIDATION.md：结构、需求、素材来源和实际验收记录。

## 同一个世界中的旅行

点击导航、Logo、浏览器前进 / 后退，或使用原生滚动，均进入同一个 CameraController。六个地标依次是首页、最近、相册、小东西、随便写写、关于。支持 hash 深链与途中改道。

03 小东西到 04 随便写写已移除整页窗帘遮挡。桌面高档位仅有约 220ms 的右上局部树叶经过，容器为 45vw × 50svh，最多占视口 22.5%；手机关闭该遮挡，只保留位移、约 1.00–1.12 的场景尺度和透明度。手机相邻导航约 600–650ms，较远路线可稍长。

相册搬运同一个 figure / button / img 节点，关闭后返回原槽；保留按钮、键盘、横滑、Escape 与焦点返回。照片来源为空时保留自然留白。笔记本始终在窗边原节点中开合；手机使用二维缩放与封面透明度，不使用书本透视。离开窗边自动合本。

## 昼夜、五种天气与四季

AUTO 读取访问者设备的本地时间；不访问定位。太阳与月亮路径是美术化表现，不是实际天文计算。

| 本地时段 | 标签 |
| --- | --- |
| 05:00–08:00 | 清晨 |
| 08:00–16:30 | 白昼 |
| 16:30–18:30 | 黄昏 |
| 18:30–21:00 | 入夜 |
| 21:00–次日 05:00 | 深夜 |

光线预览、天气和季节都使用同一个 1200ms 外观过渡时钟。首次切换所需素材先加载并解码，准备完成后才同步提交天空、云、地景、窗框和粒子状态；加载耗时不包含在这 1200ms 内。快速选择保留最后一次意图，过期的加载结果不覆盖新选择。

| 天气 | 当前表现 |
| --- | --- |
| 晴 | 蓝天、浅色云、明亮暖光和清楚的草坡 |
| 多云 | 增加云的可见度、柔化光线、降低太阳强度 |
| 阴 | 灰蓝天空、厚云、较低饱和度与远景雾感 |
| 雨 | 暗天空、雨线、预绘制湿润色与雾、窗滴 / 檐滴；声音需主动开启 |
| 雪 | 使用有真实积雪内容的冬景绘画，并显示克制的飘雪；不只是叠加雪花 |

天气是虚构场景状态，不是实时天气预报。初始天气可低频自动变化；手动选择后本次访问保持手动天气，不被自动事件覆盖。

季节 AUTO 按设备月份采用北半球美术季节：3–5 月春、6–8 月夏、9–11 月秋、12–2 月冬。可手动切换春、夏、秋、冬。春景有嫩草和更多花，夏景保留较浓绿意，秋景使用金黄地景且前景仅留少量枝条，冬景使用雪坡、积雪屋顶和栏杆。冬天清空旧草花前景；雪天无论季节选择如何，都使用冬景作为有效地表。

小猫已删除。曾在冻结版中把猫缩小 35% 并移到屋前边缘，实际截图仍显示接地、透视和夜间色温不一致；因此采用用户允许的删除方案。当前页面没有猫的图层、呼吸动画或行为状态机，也不暗示汪意养猫。

## 性能策略与动效

只有一个 World rAF 入口：镜头、书本或外观过渡需要更新时运行；静止后停止连续调度，降水使用限频唤醒。晴天没有星点、降水或花瓣时，不重复清空空白环境画布。天空低频跟随时钟；AUTO 地景按较低频率重新预绘制，不随每个镜头帧重画。

地景、植物、窗框和云的季节 / 天气 / 昼夜着色在状态变化时烘焙到画布。旅行仅改变位移、尺度及缓冲画布透明度。没有持续全幅 CSS filter、backdrop-filter、模糊或旧窗帘 wipe。动态 CSS 变量写到负责它的局部节点。

| 档位 | 世界层与云 | 降水绘制上限 | 粒子比例 |
| --- | --- | --- | --- |
| high | 远近景；三层云，其中两层缓慢移动 | 24次/秒 | 100% |
| medium | 手机以天空、主景、前景为主；两层云 | 12次/秒 | 40% |
| low | 去掉远景与复杂遮挡；单层静止云 | 8次/秒 | 20% |

质量档位依据视口、像素比、逻辑核心数和系统减少动态设置选择；手机默认 medium，较弱配置或减少动态使用 low。手机艺术图使用 assets/mobile 下长边 1100px 的 WebP，非首屏窗景按接近场景准备。两张交叉淡入缓冲不是两套持续计算的世界。

只在桌面阵风事件触发一次轻微植物运动；不再让所有草叶持续晃动。低档位关闭复杂粒子装饰。系统减少动态及“动效关”仍保留昼夜、天气、季节与阅读功能。页面隐藏时停止视觉调度并关闭声音。

声音默认关闭，只在用户主动开启后创建本地 Web Audio 图；没有音频下载或配乐。雨声与室内距离联动。返回页面后不会自动重新开启声音。

## 编辑真实内容

| 内容 | 编辑位置 |
| --- | --- |
| 最近 | index.html 的“【修改最近】”注释附近 |
| 相册 | script.js 顶部 PHOTOS，原有六条数据及字段 src、full、caption、date、place |
| 小东西 | index.html 的“【修改小东西】”注释附近 |
| 随便写写 | script.js 的 WRITING，每页 title 与 text |

将真实图片放入 assets，填写大小写一致的相对路径，例如 assets/photo-01.jpg。full 可留空。空值或方括号占位不作为个人事实显示；加载失败保留占位。若增减 PHOTOS 数量，同时调整 index.html 中的 hanging-photo 与连续 data-photo 索引。

正文采用纯文本显示；WRITING 换行写作 \n。编辑 HTML 时将 &、<、> 分别转义为 &amp;、&lt;、&gt;。不要添加用户未提供的照片、经历、日期或身份资料。首页及关于的“网页由文杰维护”保持不变。

## Umami 与验收范围

每个页面保留一次指定脚本：

```html
<script defer src="https://cloud.umami.is/script.js" data-website-id="96161282-32cd-4d9a-9470-663d7aa265c7"></script>
```

自定义事件包括 scene_change、weather_change、season_change、time_change、sound_toggle 及打开照片；载荷限场景 / 设置枚举、开关或照片序号，不传正文、照片路径或身份信息。统计加载失败不阻断网页。线上入库情况以实际 Umami 后台为准。

素材提示词与生成记录见 ASSET-PROMPTS.md。当前 V6 的实际测试结果由 VALIDATION.md 单独记录；本说明描述已接入的实现，不将旧版本测试结果当作 V6 全部通过。手机尺寸模拟、CPU 受限对照与真实手机实测必须分别标注。最终性能改善应比较同一套场景、同一 CPU 条件下的主线程成本、掉帧和绘制次数。
